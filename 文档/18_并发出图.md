# 并发出图/出片工具（dreamina_batch）

> 2026-10-19 新增。目标：把"串行等一张出完再提交下一张"改为"先全部提交，再并发取结果"。
> 工具：`工具/dreamina_batch.py`；接口：即梦 CLI 异步模式（`--poll=0` + `query_result`）。

---

## 1. 为什么慢

实测串行批次（8 张关键帧，09:10:27 → 09:18:53）：

| 指标 | 数值 |
|---|---|
| 8 张总耗时 | **8 分 26 秒**（≈63 秒/张） |
| 单次 CLI 调用（含启动+提交） | ≈12 秒 |
| 真正排队/生成时间 | 大部分时间花在"提交后原地轮询" |

串行模式的问题：**第 1 张在生成时，第 2–8 张还没提交**，服务端并发能力完全浪费。

---

## 2. 方案：两阶段异步

```
阶段 1（提交）：所有任务 `--poll=0` 只提交 → 拿 submit_id（并发 2，避免 SQLite 写锁）
阶段 2（轮询）：多个线程同时 `query_result`，谁先完成谁先下载（并发 6）
阶段 3（续跑）：manifest.json 记录状态；重跑时 --resume 跳过已完成
```

工具行为：
- 提交遇到 `ExceedConcurrencyLimit` / `database is locked` / 网络超时 → 指数退避重试（最多 4 次）；
- 轮询失败不扣费；成功以 `credit_count` 对账；
- 产物命名 `<name>.png/.mp4`；manifest 记录提交/轮询耗时、积分、文件。

### 预期收益

| 批次 | 串行实测 | 并发预期 |
|---|---|---|
| 8 张图 | 8m26s | **≈2–3 分钟**（提交 ~12s + 并发轮询/下载） |
| 16 张图 | ≈17 分钟 | ≈3–5 分钟 |

实际下限取决于即梦服务端对该账号的图像并发数；工具会自动退避。

## 3. 用法

```powershell
# 1) 写批次 JSON（示例见 工具/dreamina_batch_示例.json）
# 2) 跑
python 工具\dreamina_batch.py --spec 批次.json --out-dir 参考上传/批量出图 `
       --submit-workers 2 --poll-workers 6 --max-wait 1800

# 断点续跑（跳过 manifest 里已成功的）
python 工具\dreamina_batch.py --spec 批次.json --out-dir 参考上传/批量出图 --resume

# 自测（不调用 API、0 积分，验证并发编排）
python 工具\dreamina_batch.py --self-test --out-dir $env:TEMP\batch_selftest
```

### 批次 JSON

```json
{
  "defaults": {"model_version": "5.0", "ratio": "16:9", "resolution_type": "2k", "generate_num": 1},
  "jobs": [
    {"name": "K_U20", "mode": "image2image", "refs": ["S3.png", "C4.png"], "prompt": "..."},
    {"name": "P6_水壶", "mode": "text2image", "prompt": "..."}
  ]
}
```

- `mode`：`text2image` / `image2image` / `image2video`；
- `image2image` 的 `refs` 第一张决定构图/主体身份（见方法文档"第一张图=主角身份"）；
- `image2video` 也支持，但**视频并发通常=1**，并发收益很小（见下）。

## 4. 并发上限与坑（实测）

| 类型 | 实测行为 |
|---|---|
| 图像（Seedream 5.0） | 可同时提交多张；本次自测编排 8 任务/1.8s；真实批次建议 submit-workers=2、poll-workers=6 |
| 视频（Seedance） | **账号视频并发=1**：并发提交会报 `ret=1310 ExceedConcurrencyLimit`（本次 15s 测试连报 7 次，0 扣费） |
| seedance2.0 / 2.0fast | 当前队列极长（探针 queue_idx 17344/234086 ≈ **10 小时**），不适合当天看效果 |
| seedance2.5 | 720p 20 分/秒、480p ≈12 分/秒；约 16 分钟出片，适合测试 |

> 结论：**并发出图收益大；并发出视频无收益**（还容易撞并发上限），视频测试优先用 2.5。

## 7. 出图后自动上画布（N×N 模块化布局）

- 工具：`工具/canvas_link_images.py`
- 用法：
```powershell
python 工具\canvas_link_images.py --dir "参考上传/无归原_资产/关键帧_三锚点" --layer anchors --cols 5 --badge 三锚点 --prune-edit
python 工具\canvas_link_images.py --prune-edit    # 只清自动导入 edit 层 + 重排
```
- 行为：按文件 hash 去重、跳过已上画布 src、跳过 `_` 开头联络图；把图片加入指定层；再按模块 N×N 网格 + shelf 排列，**0 重叠**。
- 当前 b2 布局（80 卡）：overview 2×1 / chars 2×2 / props 2×3 / crowd 2×1 / scene 2×3 / test 2×2 / kf 3×3 / anchors 5×5 / history 5×5 / video 1×1。
- 画布监听会持续把 `即梦产物` 自动塞进 `edit` 层；每次生成后跑一次 `--prune-edit` 即可保持整洁。


## 8. 画布按钮修复（2026-10-19）

- 页面为静态文件，改完**刷新即可**（服务器已确认返回新代码）；浏览器缓存重时用 Ctrl+F5。
