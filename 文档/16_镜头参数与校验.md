# 镜头参数表与校验（参数化视频语言 · 本地落地）

> 目的：把「运镜」从代码里的硬编码字典，升级成 **一份可校验、可复用、可编译的数据文件**。
> 这是 V1000 那套“参数化”里唯一真正能落地的一半：参数 → 校验 → 编译 → 真实渲染器执行。
> 版本：2026-10-19 v1.2（V1000 四段式提示词层 + 双轴渲染 + 主流水线接入）· 对应脚本 `工具/shot_params.py`、schema `工具/镜头参数.schema.json`

---

## 0. 数据流

```
镜头分组.json + 运镜位移.json（+ 人工运镜覆盖 分析/运镜指定.json）
   → [build] 镜头参数.json（分析/ 与 人物替换_NIGHTDANCER/分析/宗门新功法/ 各一份）
   → [validate] schema 校验 + 语义校验（时间轴/帧数/方向/符号）
   → [compile] 渲染作业/K##.json（含双轴 x_px/y_px）
   → [render_one_shot.py] Blender 正交相机双轴关键帧真实渲染
   → [render_pipeline.py] 默认直接读 镜头参数.json（缺文件回退 MOTION）
```

---

## 1. 为什么要有这一层

现状（2026-10-18 之前）：

- 运镜参数写死在 `工具/render_pipeline.py` 的 `MOTION` 字典里（`K01: ('y', +1, 380)`）；
- 测量结果在 `分析/运镜位移.json`，人工运镜表在 `项目记忆.md` 第 5 节，两者和代码**三处各存一份**；
- 改一镜要动代码，且没有校验——轴写错、符号反了、帧数和时长对不上，只能等渲染完看片才发现。

升级后：

| 问题 | 现在 |
|---|---|
| 参数在哪 | `镜头参数.json`（唯一事实源；`SHOT_PARAMS` 环境变量可换） |
| 对不对 | `validate`：schema + 语义检查（20 镜全绿） |
| 怎么进渲染 | `compile` 生成 `渲染作业/K##.json`；`render_pipeline.py` 也直接读参数 |
| 人工指定运镜 | `--overrides`/`分析/运镜指定.json` 覆盖（`source: manual`），不污染测量数据 |
| 双轴运动 | `x_px/y_px` 双轴关键帧，斜向镜头不再丢次轴位移 |

---

## 2. 符号约定（重要，别搞反）

- `content_shift_px`：**内容位移**，图像坐标（右 +，下 +），来自帧差/相位相关测量。
- `camera.travel_px`：**相机位移** = `-content_shift_px`。相机反着走，画面内容才朝测量方向移动。
- 渲染作业字段：
  - `x_px`：相机水平位移（右 +），世界 x 同向；
  - `y_px`：相机垂直位移（下 +），世界 **-Z**（屏幕上方 = 世界 +Z）；
  - `axis/sign/px`：旧单轴字段，保留兼容；新作业同时带 `x_px/y_px`，旧 `render_one_shot.py` 调用方式不受影响。

例：`K01` 内容右移 220px → 相机左移 220px → `x_px=-220, y_px=0` → 渲染出来内容右移 220px。

---

## 3. 阈值与近似

| 规则 | 值 | 说明 |
|---|---|---|
| 静帧判定 | 主轴位移 < **8px** | 记为 `mode: static`，不渲染，合成时用静帧 |
| 斜向判定 | 次轴/主轴 ≥ **25%** | 记 `diagonal: true`（`approx` 仅表示“当时渲染器单轴”，现已支持双轴，保留字段兼容旧数据） |

> 宗门新功法 18 个运镜镜头里有 12 个是斜向；双轴渲染上线后这些镜头都能按真实位移渲染，不再近似。

## 6.1 画布联动（④ 的用法）

画布每张 `out:K##` 卡新增两个字段（不改原有 `motion`，不新增卡）：

```json
{
  "key": "out:K02", "motion": "从右往左",
  "camera": {"mode":"pan","source":"manual","axis":"x","sign":-1,"px":180,"x_px":-180,"y_px":0},
  "motion_camera": "相机左移（从右往左） 180px"
}
```

三个命令（默认 dry-run，`--write` 才落盘）：

```powershell
# 只读对比：参数 vs 画布
python 工具\sync_motion_board.py check

# 参数 → 画布（写 camera / motion_camera）
python 工具\sync_motion_board.py push --write

# 画布 → 参数（读 card.camera；缺 camera 时回退解析 motion 文本）
python 工具\sync_motion_board.py pull --write --apply   # --apply 写回并跑校验
```

- 默认打 `http://127.0.0.1:17800` 的**当前画布**；`--canvas-url` 可指到别的实例；
- 服务没开时用 `--no-http --project <项目根> [--board b4]` 直接改 `_canvas/boards/<id>/board.json`（写前备份，不碰 `board.bak.json`）；
- 画布 UI 目前不显示 `camera`（`motion` 文本也不显示），编辑走卡片 patch API；`pull` 对没有 `camera` 的旧卡会自动按 `motion` 文本方向推断，所以**现有画布不改也能直接接入**；
- 约束：只改已有 `out:K##` 卡、不新增/删除卡、不覆盖人工 `motion` 文本（遵守项目铁律）。

闭环：

```
画布改运镜（camera 字段）
  → python 工具\sync_motion_board.py pull --write --apply
  → python 工具\shot_params.py validate
  → python 工具\shot_params.py compile
  → 画布 🎬 一键渲染（render_pipeline.py 读 镜头参数.json）
```

## 7. 输入格式兼容

`build` 同时认两种历史格式：

| 格式 | 来源 | 结构 |
|---|---|---|
| A（新） | `人物替换_NIGHTDANCER/分析/宗门新功法/镜头分组.json` | `{video,width,height,fps,duration,shots:[{key,start,end,mid,frames,file,shift_px,per_sec_px,motion}]}` |
| B（旧） | 项目根 `分析/镜头分组.json` + `分析/运镜位移.json` | 分组 `[{k,start,end,mid}]` + 位移 `[{k,t0,t1,dx_1920,dy_1920}]`，运镜由 `分析/运镜指定.json` 人工指定 |

> Windows PowerShell 写出的 JSON 可能带 BOM；工具已用 `utf-8-sig` 读取。

## 8. 与 V1000 的关系

- V1000 的“参数”只到提示词层，没有 schema、没有校验、没有执行端；
- 本文件把参数做到 **数据 + 校验 + 编译 + 渲染器执行 + 实测验证**，是“可编程参数化”里真正可编程的那部分；
- 不引入对方代码与许可证（GPL-3.0 / CC BY-NC-SA），只做方法萃取与本地实现。
- 有用的一半（四段式结构 / 物理量纲词表 / 情绪节奏表）已抽成 **§9 提示词层**；执行端仍以本文件为准。

## 9. V1000 四段式分镜模板（提示词层 · 写实灾难版）

> 2026-10-19 增补。来源研究见 `分析/Parameter-Plan-V1000/V1000_基础启动指令_研究.md`。
> 只萃取其**四段式结构 + 物理量纲词表 + 情绪节奏表**作为提示词层；schema / 校验 / 编译 / 渲染仍是第 1–7 节，不因 V1000 改动。

### 9.1 每镜四段式（写视频提示词时逐段填）

```text
场景/渲染描述：起始画面（颜色/材质/状态）+ 光照（光源类型/色温K/照度lux/反射率%）+ 特效 + 背景细节
角色与动作：角色名 + 姿态/动作/微表情（引用 C1–C4 / P1–P5 资产，不另造角色）
运镜与摄影参数：镜头（景别/焦段/光圈）+ 运动（速度/方向/方式）+ 与 镜头参数.json 的对应
音效设计：环境音 + 动作音 + 人声（无对白）+ 音效密度 + 后期目标电平 dB
```

### 9.2 写实灾难版参数词表（替代 V1000 的工业科幻映射）

| 场景 | 色温 | 照度 | 反射率 | 雾/对比 | 典型音效 |
|---|---|---|---|---|---|
| 灰岭山口 S1 | 6500K 冷白 | 2500lux | 雪 85% / 岩石 25% | 中雾 / 高对比 | 风、雪粒、铜铃 |
| 雪坡雪崩 S2 | 6500K | 5000lux | 雪 85% | 浓雪雾 / 极高对比 | 雪崩低频轰鸣、雪粒 |
| 无归原 S3 | 5600K 阴天 | 800lux | 草 15% / 泥水 5% | 低贴地雾 / 低对比 | 死寂、泥水咕嘟、粘稠拔脚 |
| 篝火营地 S4 | 主光 1800K / 环境 6000K | 100lux | 布 12% / 泥土 8% | 低雾 / 高明暗 | 柴火噼啪、吞咽 |
| 南屿灯火 S5 | 3200K 暖 | 200lux | 泥地 10% | 薄雾 / 中对比 | 远处犬吠、风、脚步 |

### 9.3 情绪 → 节奏/音效

| 情绪级 | 标签 | 内部镜头长 | 运镜 | 音效密度 | 后期目标 |
|---|---|---|---|---|---|
| 2 | 平静/观察 | 4–6s | 缓/静止 | 低 | -35～-28 dB |
| 3 | 紧张/警觉 | 2–4s | 中/轻手持 | 中–高 | -30～-24 dB |
| 4 | 恐惧/绝望 | 3–5s | 慢/凝视 | 高 | -38～-28 dB |
| 5 | 反击/高潮 | 2–3s | 快/甩镜 | 极高 | -24～-18 dB |

> 15s 单元 = 按上表切 2–6 个内部切点；完整 32 单元应用见 `分析/归墟选段/无归原_制作/07_视频生成/V1000分镜块_全32单元.md`。

### 9.4 镜头自检清单（交付前逐项打勾）

- [ ] 四段齐全：场景/渲染描述、角色与动作、运镜与摄影参数、音效设计
- [ ] 光照写了：色温 K、照度 lux、反射率 %、雾况（不能只写"冷/暗"）
- [ ] 运镜与 `镜头参数.json` 一致（轴/符号/px/帧数）
- [ ] 音效标签为 `<声音>...</声音>`；明确"无对白、无字幕、无文字叠加"
- [ ] 负面约束齐全：同一角色只出现一次、道具不穿身、无 logo/水印
- [ ] 参考图顺序：第一张=主角身份；图生图阶段靠参考图锁身份，不靠提示词
- [ ] 时长倒推：对白字数 ÷ 4.3 + 1 ≤ `--duration`
- [ ] 首帧与动作描述一致（"高举→划弧"类动作不能配横持首帧）
- [ ] 提交前记 `user_credit` 基线；提交后按 `commerce_info.credit_count` 对账

### 9.5 边界

- V1000 的参数是**提示词层规格**，即梦/Seedance 不保证执行；dB 只作后期混音目标，不是生成指令；
- 本文件仍是唯一事实源（schema + 校验 + 编译 + 渲染）；V1000 只做提示词与自检的补充层；
- 不复制 V1000 原文进仓库，只做方法萃取。
