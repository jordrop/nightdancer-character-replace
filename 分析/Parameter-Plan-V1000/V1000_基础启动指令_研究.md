## 2. 它是什么（定位）

一份**给聊天 AI 用的系统提示词（System Prompt）**，不是资料库：

- 系统名称：异常协议视觉转化引擎 V1000
- 核心功能：**将任意文字剧本 → 基础工业化分镜脚本**
- 使用方式（据上游流程文档）：把整段粘进新对话窗口 → 通用 AI 被切换成"V1000 引擎" → 输入剧本 → 输出标准化分镜

也就是说：它"限制 AI"的方式是**角色 + 规则 + 输出格式**，只在当前对话生效，没有持久记忆；模型是否遵守无强制力。

## 4. 关键判断

### 4.1 有效的地方（我们已实测）

- 参数块对 **text2image（文生图）** 有明显作用：C3 顾青 v2 加上"5600K/800lux/背景反射率 18%/棉布 12%"后，整体更暗（亮度 −26%）、更灰（饱和 −43%）、服装从卫衣纠正为深灰厚棉衣；
- 对 **image2image（图生图）** 几乎无效：S1 加参数后 R/B 只变 2%，参考图完全主导；
- 因此它的正确用法是：**概念图/设定图阶段用参数块，分镜图阶段靠参考图锁，视频阶段用运镜/音效表。**

### 4.2 不能直接用的地方

1. **语境错位**：整套自动转化规则是"工业科幻/警报/护盾/能量/枪声"；《无归原》是雪原/沼泽/篝火/生存。直接套会把"暴雪"映射成"暗红应急灯 620nm/频闪 4Hz"这类错误；
2. **伪精确**：即梦/Seedance 不保证执行 K/nit/nm/dB 这些数值，图像端只能当相对描述词；dB 更适合当**后期混音目标**，不是生成指令；
3. **运镜表太窄**：只有 5 种，且没有位移量；我们的 `镜头参数.schema.json` 已有 11 种模式 + px 位移 + 速度，V1000 的运镜层不能替代；
4. **音效无法精确生控**：Seedance 只认 `<声音>描述</声音>` 这类标签，四段式里的"电平 dB"只能写进提示词当修辞；
5. **不是工作记忆**：粘贴才生效，没有 schema/校验/持久化，不应当作项目规则执行。

### 4.3 与我们的体系关系

| V1000 | 我们已有的 | 关系 |
|---|---|---|
| 物理量纲库 | `镜头参数.schema.json`（camera/mode/axis/px） | 互补：V1000 补光照/材质词表，我们补位移/速度数值 |
| 运镜规范 | `render_one_shot.py` + shot_params | 我们的更精确，V1000 只作语义标签 |
| 节奏模型 | 无归原 32×15s 时间线 + 单元 beat | 可把 2-4s/3-5s 映射到单元内部镜头切分 |
| 四段输出 | 时间线 JSON（prompt/camera/audio/emotion） | V1000 的音效段可补我们缺失的音频字段 |
| 自动转化 | 无（我们靠手动 prompt） | 需要重写"写实灾难版"映射才能用 |

## 6. 使用建议（不踩坑）

1. **不要整段注入**当总系统提示词——会引入工业科幻词汇和"伪精确"参数，污染《无归原》写实基调；
2. **只抽 4 张表**：物理量纲词表、运镜语义表、情绪节奏表、四段式模板；
3. 图像端：把"参数块"接在 prompt 末尾（已验证 text2image 有效，image2image 无效）；
4. 视频端：把"节奏 + 音效"转成 Seedance 的 `<声音>` 标签与 `--duration` 结构，dB 留给 ffmpeg 混音；
5. 落盘位置建议：`分析/Parameter-Plan-V1000/V1000_基础启动指令_研究.md`（本文件）+ `无归原_制作/_V1000参数版提示词.md`（已有），不要复制原文进仓库。
