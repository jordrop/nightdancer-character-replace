**关键发现：** Slate 的 `storyboard.json` 镜头字段是：

```json
{"id":"S1","dur":3.6,"cam":"wide","pos":[0,2,-6.2],"look":[0,1.1,0],
 "fov":48,"scene":"room","pose":{"c":"seated"},"move":"全景·固定·平视",
 "action":"三人围案而坐…","lines":[{"at":1.2,"dur":2.2,"speaker":"c","line":"…"}],
 "prompt":"全景固定机位平视…"}
```

这就是我们 `镜头参数.json` 的“3D 相机版”：`pos/look/fov` 是真正的相机参数，能直接喂 Blender 透视相机（我们现在是正交 + 单轴像素平移）。**这是最值得抄的一处。**

## D. 结论与建议

1. **“参数化提示词系统”不稀缺**：`video-notation-schema`（2025-07，Apache-2.0）已经把这件事做成了 JSON Schema，`seedance2-skill`（4.3k★）已经覆盖 Seedance 的镜头语言与模板。V1000 的“全球首创”主张在这些既有项目面前站不住——这和我们前几轮的判断一致。
2. **我们的组合没有完全同款**：Slate 是“工作台 + 白模预演”，Genjustsu 是“AI 端到端替换”，popnow-blender 是“Blender 白模 → AI 渲染”，shotpilot 是“运镜分析”。没人把 **关键帧替换 + 测量运镜 + Blender 相机还原 + 原音轨精确合成 + 自建画布** 完整拼在一起——这条差异化链路仍是我们的资产。
3. **最值得抄的三处**（按性价比）：
   - **Slate 的镜头 3D 相机字段**（pos/look/fov）→ 升级 `工具/镜头参数.schema.json` 的 v2（现在只有单轴 px，斜向镜头 12/18 个都只能近似）；
   - **video-notation-schema 的字段分层**（global / lighting / audio / shot）→ 需要给“即梦生图 prompt”做结构化时直接套；
   - **Genjustsu 的 draft→approve→final 纪律** → 画布加一步“草稿确认”再花积分出 2K。
4. **不建议直接用**：MoCha 无 license；popnow-blender 是 GPL-3.0（与我们 MIT 主线冲突）；Toonflow/waoowaoo/Jellyfish 这一层平台体量远超需求。
